\section{Introduction}

We consider phylogenetic trees that are binary and rooted, with $n$ labeled leaves. 
There are $n-1$ internal nodes including the root.
Such trees are usually represented as a mixture
of discrete and continuous variables \citep{Paradis2006}. The topology of the tree is discrete and there are 
$(2n-3)!!=\frac{(2n-2)!}{2^{n-1}(n-1)!}$ unique possibilities \citep{Felsenstein1978b}. 
The branch lengths are continuous, and there are $2n-2$ branch lengths
taking values in $\mathbb{R}_{>0}$ (one for each leaf and non-root internal node). This mixture makes it difficult
to sample the space of trees. For example, Markov Chain Monte-Carlo (MCMC) methods \citep{Gilks1996}
need to propose updates
to both the branch lengths and the topology, using moves such as nearest-neighbor interchange (NNI)
or subtree pruning and regrafting (SPR). These moves have been the workhorse of Bayesian phylogenetics
for the past 30 years but are not easy to optimise \citep{hohnaGuidedTreeTopology2012,zhangUsingParsimonyGuidedTree2020}. 
Several MCMC algorithms can be applied only to continuous variables and have therefore not
been applied to Bayesian phylogenetics. This includes 
Hamiltonian Monte-Carlo (HMC) methods which
can only deal with continuous variables \citep{Betancourt2017}. 
A continuous representation of phylogenetic tree is given by the Billera‐Holmes‐Vogtmann (BHV) 
space \citep{Billera2001}, which is made of one orthant
for each topology, connected between themselves at the points where a branch length degenerates
to zero to switch from one topology to another. But this construction is difficult to use in Bayesian
phylogenetic inference. Here we propose a new continuous parametrisation of phylogenetic
trees, and show that it enables new MCMC methods to be used for Bayesian phylogenetic inference.

\section{New continuous parametrisation}

Here we propose a new continuous parametrisation for binary rooted phylogenetic trees.
We consider an arbitrary but fixed order in which the leaves are added to the tree.
Let $L_{i-1}$ denote the sum of the branch lengths in the tree formed by the first $i-1$ leaves.
For the first leaf ($i=1$) there is nothing to specify but from the second leaf ($i=2..n$) 
two parameters need to be specified, $a_i$ and $b_i$ which both take values in $\mathbb{R}$.
The parameter $a_i$ determines the point on the tree built so far where the new leaf is grafted.
The parameter $b_i$ determines the length $\mathrm{exp}(b_i)$ of the branch separating the new leaf 
from this grafting point. 
The parameter $a_i$ represents the length
of the path from the root of the tree to the grafting point, following a contour traversal started at the root of the tree.
The contour traversal algorithm is defined recursively as follows: start from a given point, 
move down to its first child, performs the contour traversal from this first child, then move back up from the first child to the 
starting point, then move down to the second child, perform the contour traversal from the second child, and then move
back up to the starting point. If the contour traversal comes back to the root after having explored both children,
which happens if and only if $a_i>2L_{i-1}$,
then the grafting point is above the root by the remaining amount $a_i-2L_{i-1}$. 
Likewise, if $a_i<0$ then the grafting point is above the root by the amount $-a_i$.
We can deduce the following recursive formula for the sum of the branch lengths:
\begin{equation}
L_i=\begin{cases}
0 & \text{if $i=1$}\\
L_{i-1}+\mathrm{exp}(b_i)+\mathrm{max}(0,a_i-2L_{i-1})+\mathrm{max}(0,-a_i) & \text{otherwise}
		 \end{cases}
\end{equation}

The parametrisation of $a_i$ using a contour traversal is illustrated in Figure \ref{fig:contour}.
At the graft point, a new node is created with left child equal to what was previously below that point,
and right child equal to the new branch of length $\mathrm{exp}(b_i)$ leading to the leaf number $i$.
This process is repeated for all leaves from the second one ($i=2$) to the last one ($i=n$), each time
using the contour traversal on the tree built previously.

This parametrisation has the advantage to create no discontinuity,
or no jump from one part of the tree to another. It has the disadvantage to represent each grafting point
exactly twice, since each point of the tree is traversed first as the algorithm goes down the branch and then
again as it goes back up the branch. This is not ideal but is the price to pay to achieve continuity, and we
will see that it is not a problem in practice. 
Let $C=(a_i,b_i)_{i=2..n} \in \mathbb{R}^{2n-2}$.
$C$ defines a unique phylogenetic tree $T$, which can be reconstructed by considering adding the leaves
one by one as described above. Conversely, each unique phylogenetic tree $T$
can be obtained by several values $C$ due to each grafting point having two equivalent values of $a_i$.
There are therefore $2^{n-1}$ unique values of $C$ for each phylogenetic tree $T$.

\section{Application of the adaptive Metropolis sampler to the continuous phylogenetic space}

We consider a prior distribution on the tree $T$ such that all of the $(2n-3)!!$ topologies are equally
likely and the branch lengths $l_i$ follow an Exponential distribution with mean $\theta$, so that:
\begin{equation}\label{eq:tree-prior}
p_T(T)=\frac{1}{(2n-3)!!}\prod_{i=1}^{2n-2}\theta^{-1}\exp\left(-\frac{l_i}{\theta}\right)
\end{equation}

To find the corresponding distribution on $C$ we need to consider the Jacobian of the function
$f: C \rightarrow T$:
\begin{equation}
\left| \mathrm{det} \frac{\partial f(C)}{\partial C}\right|=\mathrm{exp}\left( \sum_{i=2}^n b_i\right)
\end{equation}

When accounting for this and the multiple representations of each $T$ in the space of $C$ we obtain the probability density function of $C$:
\begin{equation}\label{eq:tree-prior2}
p_C(C) = 
\frac{1}{2^{n-1}}p_T(f(C))\mathrm{exp}\left( \sum_{i=2}^n b_i\right)
\end{equation}

To sample from this distribution, we use the adaptive Metropolis sampler \citep{Vihola2011}. 
This algorithm uses a multivariate normal distribution as the proposal kernel
$q(C'|C)$ which is symmetric ($q(C'|C)=q(C|C')$), so that the acceptance probability 
is simply $\mathrm{min}(1,p_C(C')/p_C(C))$ calculated using Equation \ref{eq:tree-prior2}.
The mean of the proposal kernel is the current value $C$ and 
its covariance matrix is tuned to achieve an acceptance
rate of 0.234 \citep{Andrieu2008}. 
We take $n=5$ as a small example, with $\theta=2$ as the mean of the distribution of branch lengths.
The sampler was run for $2\times10^{5}$ iterations, with the first half discarded
as burn-in and the remainder sampled every 100 iterations to produce a sample
of size 1000. This run took less than a minute on a standard laptop. 
Figure \ref{fig:mcmc} shows that the trees sampled by the MCMC are distributed as 
expected under Equation \ref{eq:tree-prior}. All $(2n-3)!!=105$ topologies have been sampled,
the distribution of the sum of branch lengths and of a single branch length are as expected,
and a majority-rule consensus tree looks completely star-like. The effective sample size
was greater than 200 for individual branch lengths as computed using the R
package coda \citep{Plummer2006}. The approximate effective sample size
of the tree topology was also greater than 200 as computed by the R package
rwty \citep{Warren2017}.

\section{Application of  Hamiltonian Monte Carlo (HMC) to the continuous phylogenetic space}

We use the dynamic Hamiltonian Monte Carlo (HMC) method implemented in Stan
\citep{Carpenter2017,Betancourt2017}. The target distribution is as defined in 
Equation \ref{eq:tree-prior2}. 
The MCMC was run for a total of $2\times10^{5}$ iterations, with the first half discarded
as burn-in and the remainder sampled every 100 iterations to produce a sample
of size 1000. This run took less than a minute on a standard laptop. 
Figure \ref{fig:hmc} shows that the trees sampled by the MCMC are distributed as 
expected under Equation \ref{eq:tree-prior}. All $(2n-3)!!=105$ topologies have been sampled,
the distribution of the sum of branch lengths and of a single branch length are as expected,
and a majority-rule consensus tree looks completely star-like. The effective sample size
was greater than 200 for individual branch lengths as computed using the R
package coda \citep{Plummer2006}. The approximate effective sample size
of the tree topology was also greater than 200 as computed by the R package
rwty \citep{Warren2017}.
